# Alert Overview

This document contains a description of the alerts generated by this helm chart as well as an explanation of the label and annotation conventions for these alerts.

## Alert Labels

The following alert labels are added to all alerts:

| Label | Possible Values | Description |
|-------|:---------------:|-------------|
| `severity` | `critical`, `error`, `warning`, `notice` | <p>A label to broadly categorize the impact an underlying issue has when this allert is triggered. Currently, the following values are used:</p><ul><li>**Critical**: Loss of service or application availability or severe degradation of performance. Requires immediate attention.</li><li>**Error**: Degradation of performance or loss of availability of some aspect of an application or service. Requires attention but not immediate.</li><li>**Warning**: A problem that doesn't include any current loss in availability or performance, although it has the potential to lead to more severe problems if unaddressed.</li><li>**Notice**: Doesn't indicate a problem but provides interesting information which might indicate something later becoming a problem</li></ul> |
| `opendeskComponent` | `services`, `matrix`, `diagrams`, `nextcloud`, `openXChange`, `xwiki`, `nubus`, `openProject`, `jitsi`, `collabora` | A freeform label to categorize which part of OpenDesk is affected by the indicated problem |
| `baseAlertname` | | The name of the alert without the opendesk component, e.g. `OpendeskServiceUnready` instead of `OpendeskJitsiServiceUnready` |

## Alert Annotations

| Annotation | Description |
|------------|-------------|
| `summary` | A short, one-sentence statement of what is wrong |
| `description` | A longer, more detailed description of what is wrong. This also often includes the value of a metric that caused the alert to trigger (e.g. 99% memory exhaustion). |
